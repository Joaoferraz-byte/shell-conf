# Livara user-support assets

This directory contains application adapters, templates and small user-session helpers consumed by `shell-conf`'s `homeModules.support`. It is not a compositor, desktop shell, session manager or wallpaper service.

Noctalia v5 owns the visible bar, launcher, panels, wallpaper, theme palette, native templates and shell IPC. The adapter scripts consume the palette rendered by Noctalia under `$XDG_STATE_HOME/livara/theme` and write only documented formats for applications without a native Noctalia template, including the Matugen-generated IntelliJ color scheme. All generated files are mutable runtime outputs and remain outside this source tree.

Fastfetch uses the transparent cat asset from `src/livara/assets/fastfetch-cat.png`; the Noctalia bar's `control-center` button uses the supplied Japanese Kanji SVG from `noctalia-conf/assets/japanese-kanji.svg`. The theme adapter recolors only the cat's opaque pixels with the active `primary` role and keeps the high-resolution alpha edges intact. Fastfetch sends it through `kitty-direct` with an explicit 16×9 cell box, equal horizontal padding, and a four-row top offset: the 17-row text frame has center 8.5 while the 9-row logo has center 4.5, so the offset aligns both centers. The source content ratio is 1296/1518 ≈ 0.854, close to the terminal-cell-compensated 16×0.5/9 ≈ 0.889.

The runtime contract is dark-first and wallpaper-derived. The Xournal++ adapter writes `palettes/tokyonight.gpl` as a drawing palette only and changes the native canvas background, selected-page border, active palette and menu visibility; the page template, page color and graph grid remain user-owned. A Home Manager user service runs at graphical-session start and a path unit reruns it whenever Noctalia changes `palette.dark.json`. The `sync-livara-themes` entry point creates Foliate, Freesm Launcher, Heroic, IntelliJ/Android Studio, Nuclear and Hydra contracts when their application profiles or state roots exist. Hydra receives a CSS export under Electron's `userData/themes/<theme-id>` path and a mirrored artifact in the official hydra-themes publication layout; the Appearance list is LevelDB-backed and requires the supported Create/Edit flow for activation. Nuclear receives a v2 advanced-theme JSON and its flat settings keys are selected in every existing native or Flatpak AppData root. Firefox profile chrome, Material Fox base files and Zen Browser profiles are owned by the declarative `nix-conf`/Noctalia integration. Nixvim consumes its palette directly, while this repository owns only the shared Noctalia templates and non-native application adapters.

IntelliJ IDEA and Android Studio receive both the editor scheme and a local UI-theme plugin under each product's `plugins` directory. A UI theme is necessarily provided by a plugin in the IntelliJ Platform; it cannot be installed as a standalone theme file. The adapter writes the provider's id to `options/laf.xml`, so the theme is selected by default after the next IDE restart, while the plugin remains visible in Plugins as required by the upstream contract. Nuclear updates its documented advanced-theme JSON and, only while the process is absent, selects its absolute path through the upstream settings store; this is a version-sensitive contract protected by validation and atomic replacement. Hydra's CSS is placed in its documented user-data theme directory and mirrored for publication, but the Settings > Appearance list is backed by a private LevelDB record and does not discover files from that directory. The adapter therefore does not mutate Hydra's private database or claim activation; using the native Create/Edit flow remains the supported operation.

The tablet status helper reports the physical MTM-1106/T501 USB device and stable external tablet symlinks. Hardware enablement, udev rules, drivers, portals, audio policy and power services remain owned by `nix-conf` and their feature repositories.

The package does not install a second shell process, a second palette generator, a compositor, a wallpaper daemon or an idle daemon. Keyboard bindings and Noctalia IPC calls remain in the declarative Niri module of `nix-conf`.
