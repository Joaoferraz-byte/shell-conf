# shell-conf

This repository provides shell-independent user support for the Livara NixOS environment. The visible desktop shell is **Noctalia v5**, owned by `noctalia-conf`; this repository does not start a shell, patch a compositor, or own wallpaper/palette generation.

## Architecture

| Responsibility | Owner | Interface |
|---|---|---|
| Host, hardware, drivers, services, Niri and system capabilities | `nix-conf` | NixOS and Home Manager modules |
| Bar, launcher, panels, notifications, wallpaper, widgets and palette | `noctalia-conf` | Noctalia v5 TOML, plugins and IPC |
| Application adapters and user support | This repository | `homeModules.support` |
| Vim configuration and editor theme policy | `vim-conf` | NixVim module consuming `matugen_colors.lua` |

The exported `homeModules.support` provides Fastfetch, WezTerm configuration, tablet detection, Xournal++ and Daily-note helpers, GTK preference files and non-native application theme adapters. Nixvim and its Markdown workflow are consumed directly from `vim-conf`; this repository supplies the shared palette and application support around the editor. The visible shell, compositor and idle policy remain owned by their dedicated modules.

The note helpers use explicit session paths: `LIVARA_TEMPLATE_DIR` points to `Vault/06 - Config/templates`, `LIVARA_DAILY_DIR` to `Vault/03 - Daily Notes`, `LIVARA_IMAGE_DIR` to `Vault/00 - Black Box/Assets/Images`, and `XOURNAL_TEMPLATE_PATH` to the versioned `Vault/06 - Config/templates/Xournalpp.xopp` template. `livara-daily-note` expands the small set of local `{{title}}`, `{{date}}`, `{{date:FORMAT}}`, `{{time}}`, `{{week}}` and `{{cursor}}` placeholders and supports `--no-open` for NixVim delegation; no external note runtime is required.

Fastfetch uses the transparent cat reference from `src/livara/assets/fastfetch-cat.png`. The theme adapter recolors only its opaque pixels with the active `primary` role and sends it through `kitty-direct` with a 16×9 terminal-cell box calibrated against the source content ratio.

## Theme flow

Noctalia is the single palette owner. Its versioned user template writes an atomic palette under `$XDG_STATE_HOME/livara/theme/palette.dark.json` and invokes `sync-livara-themes`. That script consumes the palette and writes only documented native formats for applications that lack a Noctalia built-in template, such as Foliate, Freesm Launcher, Heroic and Xournal++. The Livara profile provides cmus as the terminal music player; cmus owns its interactive terminal configuration and has no adapter here. Nixvim consumes the palette through the Lua file generated by `nix-conf`, while the browser bridge consumes Noctalia-generated Firefox CSS from `$XDG_STATE_HOME/livara/theme/browser/` and links it into Firefox profiles without overwriting user content. Zen Browser CSS, userChrome, profiles, containers and session stores are owned declaratively by `nix-conf` and Noctalia.

The built-in Noctalia templates own GTK, Qt, Kitty, WezTerm, Starship and KDE outputs. This repository therefore does not overwrite those files or run a second Matugen process. NixVim keeps its existing highlight policy from `vim-conf`; Noctalia writes the Lua palette file expected by that module and sends a best-effort reload signal to running Neovim instances.

## Nixvim and Markdown boundary

The Vault repository owns Markdown notes and Xournal++ documents. `vim-conf` owns the Nixvim editor, Treesitter/Marksman language support, in-buffer Markdown rendering, Mermaid tooling, LaTeX-aware preview decisions, file explorers and workflow keymaps. `nix-conf` owns the Home Manager composition, the palette file consumed by Nixvim, generic Vault synchronization and Xournal++ desktop integration. No Obsidian runtime, plugin materializer, JavaScript dashboard, or `.obsidian` state is required by the active workflow.

Markdown rendering is intentionally layered. In-buffer rendering stays in Nixvim through `render-markdown`; Mermaid diagrams use the pinned Mermaid plugin and its terminal-capable renderer. A browser preview, when enabled on the target host, is an optional trusted-local feature rather than an activation-time dependency. Xournal++ remains a native application with its own versioned configuration and does not inherit editor-specific rendering logic.

## Reproducibility and state

All active scripts and templates are versioned, and Home Manager installs them from the flake store. Application profiles, browser sessions, palette outputs and Xournal++ state remain mutable user data; the Vault's Markdown remains versioned. The fallback palette is used only until Noctalia has rendered its first wallpaper palette.

The tablet helper matches the physical MTM-1106/T501 USB identity `08f2:6811` first and uses stable `/dev/input/by-id` names as a generic fallback. The corresponding driver and udev rule remain in `nix-conf`/`mesa-tomate-driver`; this repository only reports presence to user-facing support code. Tablet presence controls the cat animation, not whether the Xournal++ creation action is available.

## Flake usage

```nix
inputs.shell-conf = {
  url = "github:Joaoferraz-byte/shell-conf";
  inputs.nixpkgs.follows = "nixpkgs";
};

home-manager.sharedModules = [
  inputs.shell-conf.homeModules.support
];
```

## Validation

Run `nix flake check --no-build` in this repository and in `nix-conf`. Validate the shell adapter scripts with `bash -n` and `shellcheck`, inspect generated paths under `$XDG_STATE_HOME/livara/theme`, and confirm that every generated file has a documented owner. On hardware, validate the application-specific contracts independently because native applications may create their profiles after Home Manager activation.
